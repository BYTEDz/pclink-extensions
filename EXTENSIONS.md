### Technical Specifications

- **Manifest Standard**: Manifest v2 (`manifest_version: 2`)
- **Package Container**: `.pclink` archive format (ZIP with root `manifest.json`)
- **Minimum Server Engine**: PCLink Server `4.8.0`
- **Minimum Client App**: PCLink Companion `4.9.0`
- **Frontend SDK**: Unified Host Broker SDK (`/extensions/sdk/pclink-sdk.js`)
- **Security Validation**: SHA-256 integrity verification on all package distributions

---

### Runtime Execution Architecture

Extensions support four distinct runtime execution models:

#### 1. Broker Mode (`runtime: "none"`)
Frontend webviews communicate directly with host system services through the Host Broker Gateway (`pclink-sdk.js`). No background process is spawned on the host, eliminating idle resource overhead.

#### 2. Supervised Python Worker (`runtime: "python"`)
Runs as an isolated subprocess managed by the host supervisor. Communicates with the core server over a bidirectional IPC pipe and exposes custom FastAPI routes.

#### 3. Supervised Node.js Worker (`runtime: "node"`)
Runs a background Node.js process managed by the server watchdog.

#### 4. Native Binary (`runtime: "binary"`)
Executes a platform-specific compiled executable (Rust, Go, C++) packaged inside the `.pclink` bundle.

---

### Security and Resource Boundaries

- **Permission Governance**: All capabilities (`system.exec`, `fs.read`, `fs.write`, `storage.local`, `input.inject`, `media.control`) must be explicitly declared in `manifest.json`.
- **Administrative Consent**: Extensions requiring dangerous capabilities or worker subprocesses are automatically quarantined upon installation until approved by the administrator.
- **Resource Enforcement**: Memory quotas and execution timeouts are clamped by the host supervisor (32 MB to 1024 MB RAM, 5s to 60s timeout ceilings) to prevent host exhaustion.
